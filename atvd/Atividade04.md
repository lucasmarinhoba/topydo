# Atividade 04 – Manutenção em Projeto Existente

Andrei Formiga — 28 de outubro de 2026

## 1. Introdução

Nesta atividade o objetivo é executar o que foi planejado na Atividade 03 (atividade de manutenção em projeto já existente) e entregar o código e o relatório sobre o projeto.

### 1.1. Não enviem código para os projetos

**Importante:** mais uma vez lembrando que o objetivo não é mandar o código gerado pelo agente para o projeto open source selecionado. Muitos mantenedores de projetos open source recebem muito código gerado por modelos de linguagem e não conseguem revisar tudo; em alguns projetos a habilidade de mandar PRs (pull requests) para usuários que não estão cadastrados foi desligada, para evitar o excesso de contribuições geradas por LLMs. Se o grupo achar interessante, pode tentar entrar em contato com os mantenedores para perguntar se eles gostariam de receber a melhoria implementada.

### 1.2. Entrega

A entrega da atividade inclui:

- **O código do projeto**, incluindo as partes originais e as partes adicionadas pelo grupo. Idealmente mandar link para um repositório contendo um fork do projeto original que inclui as alterações.
- **Documentação** especificando claramente o que foi adicionado, como fazer o build do projeto com as alterações e como testar.
- **O relatório sobre o projeto**, focado principalmente no processo de desenvolvimento com agentes e na experiência de trabalhar com um projeto já existente. É interessante relatar:
  - o que funcionou;
  - o que não funcionou;
  - se houve algo inesperado no processo;
  - qual o nível de familiaridade prévio do grupo com as tecnologias e técnicas usadas no projeto original;
  - o que o grupo aprendeu após executar essa manutenção.

Esse projeto deverá ser apresentado, em data a determinar.
